# Contributing

Thanks for contributing to the SPHF Wi‑Fi Portal Training Lab.

## Goals for contributions

Please keep contributions:

- clear and beginner-friendly
- safe to use in training environments
- based on fake/demo data only
- well-organized and easy to navigate
- consistent with the multi-discipline training focus

## Before you contribute

1. Read the files in `docs/`
2. Check whether your change fits an existing learning track
3. Prefer simple examples over production complexity
4. Add short explanations for any new concept or file

## Content guidelines

- Avoid using real personal, member, or network data
- Label placeholders clearly
- Document assumptions in plain language
- If you add code, include comments only where they improve understanding
- If you add examples, explain what learners should notice

## Pull request checklist

- [ ] The change supports training or workshop use
- [ ] The content is understandable to beginners
- [ ] Sample data is fake and clearly labeled
- [ ] File names and structure stay organized by track
- [ ] Documentation has been updated where needed

## Suggested contribution types

- improve portal pages for training
- add walkthrough notes or diagrams
- expand sample schemas or demo data
- add security review exercises
- improve network planning examples
- add learner tasks or facilitator notes
