# Topology

## Simplified components

- client device
- wireless access point
- gateway or router
- captive portal web service
- DNS service
- optional member or policy data source

## Simplified flow

1. Client associates to Wi‑Fi
2. Device gets limited network access
3. DNS and HTTP/HTTPS behavior triggers portal detection or redirect flow
4. User reaches the portal pages
5. Gateway updates the access policy after successful completion

## Discussion prompts

- Which services must be reachable before authentication?
- What breaks if DNS is unavailable?
- How should support staff tell whether a failure is a network problem or a portal page problem?
