# System Flow

This document explains the simple flow we are using in this training project.

## Step 1: A user joins the Wi‑Fi

A phone, tablet, or laptop connects to the Wi‑Fi network.

At this point, the user may not have full internet access yet.

## Step 2: The user is redirected

When the user tries to open a website, the network redirects them to the captive portal.

This is where the portal experience begins.

## Step 3: The user sees the login page

The user arrives on the login page.

Here they may:

- enter a member ID or other basic information
- give a device name
- accept terms for the training flow

## Step 4: The system checks the request

In a real system, this step could involve:

- a router or gateway
- an authentication service
- a database
- access control rules

In this training repo, we keep this part simple and use placeholders or fake examples.

## Step 5: The user gets a result

After the form is submitted, the user may be taken to:

- a status page
- a redirect page
- an error page

## Step 6: The session ends

At some point, the user may log out or the session may end.

That is why the project also includes a logout page.

## Why this flow matters

This simple flow helps attendees understand that a captive portal is not just a web page.

It is a combination of:

- front-end pages
- user flow
- data handling
- security decisions
- network behaviour
